# 미술시간 진품명품 — 개인번호·Firebase 보안 테스트 버전

기존 화면과 수업 기능을 유지하면서 실제 출석번호를 사용하지 않는 새 시스템입니다.
기존 자료 이전 기능은 없으며, 기존 운영 Firebase에 연결하거나 데이터를 삭제하지 않습니다.
기존 GitHub Pages용 루트 `index.html`은 그대로 두고, 새 앱은 `public/index.html`에서 구현합니다.
배포·기존 데이터 삭제는 사용자 확인 이후에만 진행합니다.

## 학생과 교사의 사용 방법

교사가 먼저 담당 반을 선택하고 활동을 추가합니다. 개인번호 관리 카드에서 인원수를 입력해
학생별 **4자리 무작위 개인번호와 독립적인 8자리 접속 비밀번호**를 자동 발급합니다.
`0000`처럼 앞자리 0을 허용하며, 같은 학년도·학년·반에서는 중복되지 않습니다.
다른 반은 같은 번호를 사용할 수 있습니다. 학생 회원가입이나 학생 이메일은 필요 없습니다.

학생은 기존과 같이 학년·반을 선택한 뒤 개인번호와 접속 비밀번호를 입력합니다.
인증 후 활동과 닉네임을 선택하고 작품·퀴즈·감상·좋아요·성장 다짐에 참여합니다.
학생에게는 본인 배부 카드만 전달합니다. 접속 비밀번호는 혼동되는 문자를 제외한 8자리이며
소문자로 입력해도 화면에서 대문자로 정규화합니다.

교사는 Firebase Authentication의 이메일·비밀번호 계정으로 로그인합니다.
일반 학생이 교사 화면의 브라우저 값을 조작해도 서버에서 교사 권한을 얻을 수 없습니다.
학생 번호·비밀번호 재발급은 내부 학생 ID와 이 새 시스템에서 작성한 작품·점수·다짐을 유지하며,
기존 번호와 비밀번호, 이전 로그인 세션은 즉시 서버·규칙의 인증 버전 검사에서 거부됩니다.
번호가 다시 다른 학생에게 배정되지 않도록 폐기한 번호도 예약 상태로 남깁니다.

배부 카드의 비밀번호 원문은 발급 응답과 교사 화면 메모리에서만 확인할 수 있습니다.
배부 완료 버튼, 수업 전환 또는 로그아웃으로 화면 메모리의 카드를 지웁니다.
이후 확인 화면에는 개인번호만 표시합니다. 비밀번호를 잃어버리면 재발급합니다.
작품 QR에는 개인번호·비밀번호가 들어가지 않으며, 번호 재발급 후에도 같은 작품으로 연결됩니다.

## 새 데이터 구조

| 경로 | 용도 | 접근 |
| --- | --- | --- |
| `v2Accounts/{authUid}` | 서버가 생성한 역할·수업·내부 학생 ID·인증 버전 | 활성화된 본인의 계정만 읽기, 클라이언트 쓰기 금지 |
| `v2Classes/{학년도-학년-반}` | 수업 범위 | 담당 교사·해당 반 학생 |
| `…/students/{studentId}` | 닉네임·활동·점수 | 해당 반에서 공유, 서버만 쓰기 |
| `…/activities/{activityId}` | 수업 활동 | 해당 반 읽기, 교사 서버 명령만 관리 |
| `…/artworks/{studentId__activityId}` | 이미지·작품 소개·정답 없는 퀴즈 | 해당 반 읽기, 소유자·교사 서버 명령만 수정 |
| `…/responses/{artworkId__viewerId}` | 감상·답변·점수·좋아요 | 해당 반에서 공유, 서버만 쓰기 |
| `…/reflections/{studentId}` | 성장 다짐 | 해당 반에서 공유, 본인·교사 서버 명령만 수정·삭제 |
| `…/roster/{studentId}` | 교사 확인용 4자리 번호 | 담당 교사만 읽기, 서버만 쓰기 |
| `…/credentials/{studentId}` | scrypt 비밀번호 해시·무작위 salt | 모든 클라이언트 읽기·쓰기 금지 |
| `…/codes/{4자리번호}` | 번호 예약·폐기 상태·내부 ID 조회 | 모든 클라이언트 읽기·쓰기 금지 |
| `…/quizKeys/{artworkId}` | 서버 채점용 정답 | 작품 소유자·담당 교사만 개별 조회 |
| `…/audit/{id}` | 교사 관리 작업 이력, 인증 비밀 제외 | 담당 교사만 읽기 |
| `v2LoginLimits/{id}` | 반별 IP·번호 로그인 시도 제한 | 서버 전용 |

내부 학생 ID는 무작위 UUID이며 학생 Firebase Auth UID와 동일하게 연결합니다.
출석번호·실명 대응표를 만들지 않으며, 학생 공개 문서에 개인번호나 인증정보도 저장하지 않습니다.
학생은 다른 학생의 기록을 수정할 수 없습니다. 작품·감상·답변·다짐·랭킹의 읽기는 수업 기능을
위해 **현재 반 안에서 공유**되며, 다른 반과 비로그인 사용자는 읽을 수 없습니다.
교사는 담당 반 선택을 전환해 여러 반을 관리합니다. 반을 넘는 학생 공개 전시는 기본 제공하지 않습니다.

## 인증과 서버 검증

- `studentLogin`: 번호와 비밀번호 검증 후 Firebase Custom Token 발급. 잘못된 번호와 비밀번호는
  같은 안내를 사용하고, 15분 동안 반별 IP 120회·개인번호 10회로 시도 횟수를 제한합니다.
  학교 공용 네트워크에서 한 반 40명이 함께 로그인하도록 IP 제한을 반별로 적용했습니다.
- `issueStudents`: 담당 교사 권한을 서버에서 확인하고 트랜잭션으로 번호 예약·계정 생성·재발급.
  한 반의 활성 학생은 최대 40명입니다. 동시 발급에도 중복되지 않습니다.
- `checkCodes`: 담당 반의 중복 여부와 번호 인덱스 연결 검사.
- `galleryCommand`: 작품·감상·퀴즈·다짐·활동·삭제·좋아요·베스트 답변 명령을 서버에서 검증.
  브라우저에서 보낸 점수·작가 ID·감상자 ID를 신뢰하지 않습니다.

모든 Firestore 클라이언트 쓰기를 차단하고 서버 명령으로만 기록을 변경합니다.
객관식 정답은 공개 작품 문서에서 분리하고, 기존 서술형 길이 채점 및 포인트 계산 방식을 서버에 유지합니다.
퀴즈 제출과 학생·작가 포인트 증감을 한 트랜잭션으로 처리합니다. 동일 작품 중복 제출은 거부하며,
좋아요와 베스트 답변은 목표 상태를 저장해 같은 요청을 재시도해도 중복 포인트가 발생하지 않습니다.
감상·작품 삭제 시 관련 포인트를 함께 회수합니다.

답변이 이미 제출된 퀴즈는 기존 점수의 의미를 유지하기 위해 문제·정답 변경을 거부합니다.
작품 제목·설명은 계속 수정할 수 있습니다. 한 번에 380개를 초과하는 연쇄 삭제는 부분 삭제 없이
거부하며, 그런 경우 교사가 작품별로 나눠 삭제해야 합니다.

브라우저 로그인 유지 방식은 Firebase의 탭 세션입니다. 로그아웃은 Firebase 로그아웃과
실시간 구독 해제·화면 캐시 초기화를 함께 수행합니다. 로컬 프로필로 신원을 복원하지 않습니다.
교사의 서비스 계정 키·학생 비밀번호 원문·해시를 클라이언트 코드나 GitHub에 넣지 않습니다.
교사 역할과 담당 반은 관리자가 서버 데이터로 지정하며, 이메일 입력만으로 교사 권한을 얻지 못합니다.

테스트 에뮬레이터를 제외한 Functions는 App Check를 강제합니다. App Check만으로 권한을 판단하지
않고 매 요청마다 계정 역할·수업 소속·소유권·인증 버전을 확인합니다.
현재 이미지 저장 방식은 원본과 같은 Firestore JPEG 데이터입니다. Storage는 사용하지 않으며
새 테스트 프로젝트의 Storage 규칙은 모든 접근을 거부합니다.

## 로컬 테스트 실행

Node.js 22, Java 21 이상을 준비합니다. 기본 프로젝트는 실제 Firebase 리소스가 없는
`demo-jin-gallery`이며 `public/config.js`도 로컬 에뮬레이터만 연결합니다.

```sh
npm ci --ignore-scripts
npm ci --prefix functions --ignore-scripts
npm test
npm run test:rules
npm run test:integration
npx playwright install --with-deps chromium
npm run test:browser
```

화면을 직접 테스트할 때는 두 터미널을 사용합니다.

```sh
# 첫 번째 터미널
npm run emulators
# 두 번째 터미널: 에뮬레이터가 켜진 후
npm run seed
```

`seed`가 출력한 임시 교사 이메일·비밀번호로 `http://127.0.0.1:5000`에서 교사 로그인합니다.
임시 비밀번호는 매 실행마다 새로 생성되며 코드에 저장되지 않습니다.
학년도 2026의 담당 반을 선택하고 활동 추가 → 학생 발급 → 배부 카드 인쇄 → 학생 로그인 순서로 확인합니다.
시드 스크립트는 Auth·Firestore 에뮬레이터 주소를 강제하며 운영 계정을 만들지 않습니다.

`test:browser`는 실제 HTML 화면과 서버 업무 로직을 메모리 저장소로 실행합니다.
Firebase SDK·Security Rules 통합을 대체하는 테스트가 아니며, 두 에뮬레이터 테스트도 통과해야 합니다.
브라우저 화면 테스트의 테스트 서비스는 `test/`에만 있고 Hosting 배포 대상에 포함되지 않습니다.

GitHub Actions의 `Secure gallery tests` 워크플로는 PR에서 같은 테스트를 실행합니다.
Firebase 운영 자격증명·GitHub 쓰기 권한·배포 단계는 없고 `demo-jin-gallery`만 사용합니다.

## 테스트 프로젝트 배포 방법 — 실제 실행은 별도 확인 후

1. 기존 `jin-gallery`와 다른 **새 테스트 Firebase 프로젝트**를 준비합니다. 기존 프로젝트에 이 규칙을
   배포하면 기존 앱의 접근을 막을 수 있으므로 대상 프로젝트를 반드시 분리합니다.
2. Cloud Functions에 필요한 결제 플랜과 API를 설정하고 Firestore 위치를 정합니다.
   Functions 기본 리전은 `asia-northeast3`입니다.
3. Firebase Authentication에서 이메일·비밀번호 제공자를 켜고 교사 계정을 생성합니다.
   학생 회원가입 화면은 제공하지 않습니다. Firebase 웹 앱과 App Check의 reCAPTCHA 제공자를 등록합니다.
4. 관리자 권한으로 `v2Accounts/{교사 UID}` 문서를 아래처럼 등록합니다. 학생 브라우저로 역할을 부여하지 않습니다.

   ```json
   {"role":"teacher","active":true,"classIds":["2026-3-1","2026-3-2"]}
   ```

5. `public/config.js`에 새 테스트 프로젝트의 웹 설정을 넣고 `emulator:false`, App Check 공개 사이트 키,
   학년도를 설정합니다. 웹 SDK 설정·사이트 키는 공개 설정이고 서비스 계정 비밀키는 넣지 않습니다.
6. Functions 실행 서비스 계정에 Firebase Auth 관리와 Custom Token 서명을 위한 필요한 IAM 권한을 확인합니다.
   토큰 서명 오류가 나면 IAM Service Account Credentials API와 해당 서비스 계정의 서명 권한을 점검합니다.
7. 규칙·통합·화면 테스트가 모두 통과하고 대상 프로젝트를 확인한 뒤 배포합니다.

   ```sh
   npx firebase deploy --project <새-테스트-프로젝트-ID> --only firestore:rules,firestore:indexes,functions,hosting
   # 새 테스트 프로젝트에서 Storage를 생성한 경우에만 별도로 적용
   npx firebase deploy --project <새-테스트-프로젝트-ID> --only storage
   ```

8. 새 프로젝트에서 교사·학생 2명 이상으로 번호만 로그인 거부, 타인 수정 거부, 점수 중복 방지,
   재발급 후 구 세션 차단, 인쇄, 공유 기기 로그아웃을 다시 확인합니다.

운영 공개는 이 테스트와 사용자 확인 이후 별도로 진행합니다. 기존 운영 데이터는 그대로 남겨 두며,
삭제 스크립트·이전 스크립트·운영 자동 배포 워크플로를 제공하지 않습니다.
새 시스템을 운영할 때도 기존 Firebase 프로젝트의 규칙을 덮어쓰지 않고 새 프로젝트를 사용하는 방향을 권장합니다.
